zDPlayerLocation

version 1.0.1 — by Donatier

A small plugin built for one thing: showing which country each player is from, with the tag, color and style you want for each one — without ever showing anyone their IP, just the result.

Spigot Paper Purpur Folia 1.16+ PlaceholderAPI (optional)

Introduction

When a player joins, the plugin resolves their country from their IP and builds a tag like ((VNZ)) or ((MX)) — put it in the tab list, in the join message, or use it as a placeholder in any other plugin. All 199 countries are listed in config.yml so you can edit each one to your liking: the tag, the color, and whether it's bold, italic or underlined.

Installation

  1. Download zDPlayerLocation-1.0.1.jar.
  2. Drop it into /plugins.
  3. Restart the server. config.yml and cache.yml are generated inside /plugins/zDPlayerLocation.
  4. Edit whichever countries you want and run /zdpl reload.

Privacy

To figure out someone's country, the plugin sends their IP to a free external geolocation service (ip-api.com by default, configurable in geolocation.api-url). It doesn't send any other player data, and all it stores is the resulting country code — never the IP itself. If a player connects from a local network (127.0.0.1, LAN), the plugin detects that on its own and skips the external lookup entirely, using the local tag directly.

The country is re-checked on every connection - it never sticks to an old result. If a player changes network or country between sessions, it's picked up the moment they reconnect.

Countries (name / tag / gradient / style)

Each country has its own fully editable block:

countries:
  VE: # Venezuela
    name: "Venezuela"
    tag: "VNZ"
    gradient: ["#F9EF80", "#6BD1FA", "#E65151"]
    small-caps: true
    bold: true
    italic: false
    underline: false

gradient is a list of one or more hex colors: with just one it's a solid color, with two or more the plugin interpolates the color letter by letter across the whole tag — that's how VNZ ends up with each letter in a different shade. small-caps automatically converts the tag into small caps (like ᴠɴᴢ); you don't need to type it that way yourself, just write "VNZ" normally. name is the country's full name, with no color or style — for when you want to show it "plain" instead of the tag.

default is used for any country not in the list, or when the lookup fails; local is what gets assigned to someone connecting from a local network.

All 199 countries are loaded out of the box, each with a name, tag and gradient. The most requested ones got real flag colors (all of Latin America, Spain, the United States, Germany, France, Italy, the United Kingdom, Russia, China, Japan, India, Canada...). The rest got a generic 2-tone gradient so they weren't all flat - if you want a specific country to have its real flag colors, let me know which one and I'll change it.

Tab, join and leave

display:
  format: "&8&0((%tag%&8&0))"
  tab-suffix-enabled: true
  join-message-enabled: true
  join-message: "&a+ &7%player% &7connected from &8&0((%tag%&8&0))"
  leave-message-enabled: false
  leave-message: "&c- &7%player% &7disconnected."

%tag% already comes colored and styled for that country; %name% is the country's plain name, for when you'd rather show "Venezuela" instead of "((VNZ))". tab-suffix-enabled appends the result to the end of the player's name in the tab list. The join and leave messages are toggled and written separately.

Language and messages

The plugin ships in English by default. Everything it says — commands, warnings, help — lives in a single section at the top of config.yml, so you can translate it without touching anything else: 

messages:
  no-permission: "&cYou don't have permission to do that."
  reload-success: "&aConfiguration reloaded successfully."
  # ...and the rest of the plugin's messages

Country names (name inside each block under countries) are also in English by default - it's just a plain text field, so if you'd rather have "Alemania" instead of "Germany", for example, you change it right there, country by country.

Fallback if the lookup fails

The country is resolved again every single time someone connects - it's never used as a shortcut. cache.yml only comes into play as a fallback: if the lookup fails at some point (no internet, service down), the plugin uses the last country it was able to resolve for that player, as long as it isn't older than geolocation.cache-hours hours. 

geolocation:
  cache-hours: 720
  local-ip-country-code: "LOCAL"

Placeholders

If you have PlaceholderAPI installed, these are available automatically:

PlaceholderShows
%zdplayerlocation_country%The full formatted result, e.g. ((VNZ)) with its gradient.
%zdplayerlocation_tag%Just the tag with its gradient and style, without the format's parentheses, e.g. colored VNZ.
%zdplayerlocation_name%The country's full name, e.g. Venezuela.
%zdplayerlocation_code%Raw ISO code returned by the lookup, e.g. VE.

Use them in another plugin's chat format, someone else's tab list plugin, a menu — anywhere that accepts PlaceholderAPI placeholders.

Compatibility

Built against the Spigot API (not Paper's), so it runs the same on Spigot, Paper, Purpur or Folia from 1.16 onward, without using anything Paper-exclusive. If you have PlaceholderAPI installed, the plugin detects it on startup and registers its placeholders on its own; if you don't, nothing breaks, the rest of the plugin works exactly the same.

For developers: building from source

If you downloaded the source code instead of the .jar:

cd zDPlayerLocation
mvn clean package

The final file will be at target/zDPlayerLocation-1.0.1.jar.

Requires Java 17+ and an internet connection the first time, so Maven can download the dependencies.

Support

If something's not working right or you think of something it's missing, reach out with the plugin version, your server software, and the steps to reproduce it.
